                                     III. CAPTURE METHODOLOGY
 7. The May 14, 2026 Extended Scrape Evidence datasets were captured on May 14, 2026 between
    approximately 22:14 UTC and 22:42 UTC by Defendant/Counter-Plaintiff Conrad Rockenhaus using the
    Apify platform's apidojo/tweet-scraper actor (https://apify.com), the same actor used for the May 12,
    2026 Scrape Evidence captures inventoried in the First Supplement and for the May 14, 2026 Scrape
    Evidence captures inventoried in the Second Supplement.
 8. The capture methodology was materially identical to that described in the First Supplement and the
    Second Supplement: Apify task runs were initiated with structured JSON query parameters specifying
    the target X account handles or conversation identifiers, the maximum item return count, the sort order,
    and the language filter ("tweetLanguage": "en" for all captures). Apify executed the queries against the X
    platform's public-facing API surface and returned the responsive tweet records as a JSON dataset. The
    JSON datasets were downloaded by Defendant/Counter-Plaintiff in their as-returned form, without
    modification, immediately upon completion of each Apify task run, and were stored on local disk at file
    paths under Defendant/Counter-Plaintiff's working directory in chronological order of capture.
 9. Each JSON dataset preserves the raw return payload from the Apify actor, including all metadata fields
    populated by Apify and by X Corp., for each tweet record. No record was edited, redacted, or otherwise
    modified prior to or following download.
